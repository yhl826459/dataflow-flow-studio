# 打开流水线工作台

初次使用或需要只读访问时，请先看[工作台使用指南](../WORKBENCH.md)。

## 连接 amax 上的工作台

在 amax 上启动自己的工作台服务，再从本机按[SSH 转发步骤](../WORKBENCH.md#2-通过-ssh-转发访问界面)连接。使用期间保留建立转发的窗口，浏览器通过本机回环地址访问。

网页和后端位于本人服务器账号的 `$HOME/DataFlow/flow-studio/`。流水线设计、草稿和算子模板首次修改后写入该目录的 `.local/library.json`。直接打开同一转发地址可以继续编辑。手部分割监控读取该账号的服务器任务。浏览器演练和文本处理的运行记录保存在启动它们的浏览器中。

可以在服务器上用 `systemctl --user status flow-studio.service` 查看服务状态。服务监听账户私有的 `.local/workbench.sock`，由 SSH 将它转发到 Windows 的本机端口。

已配置 API 反向转发的部署会经本机访问 ABS 接口，复用 ABS 接口的 Agent 也使用这条连接。接口地址和 ABS 检查点参数沿用原值。处理这两类请求期间保持负责反向转发的 SSH 会话在线。

## 动手编辑一个算子

1. 在编排页点击算子库中的卡片，右侧会显示输入、处理逻辑、调用模型和输出。点「编辑算子说明」，可以逐项修改，再点「保存算子说明」。库卡的说明会随下一次拖入复制到画布。要改已有节点，选中节点，编辑并保存说明，再保存流水线。也可以从算子库的设计入口新建一个 Python 记录算子。
2. 例如把新算子命名为「清理英文标签」，在默认 `run(self, storage)` 中把写入 `clean_text` 的那一行改为 `row['clean_text'] = row['text'].strip().lower()`。点「检查代码」，展开「用样例试跑」，输入 `{"text":"  Hand  "}`。输出应保留原字段并新增 `"clean_text":"hand"`。
3. 保存到算子库，再拖到画布。若要插入已有连线，先移除该线，再连接上游输出到新算子的输入，并将新算子的输出接回原下游。记录流水线在「启动任务」中选择「处理 JSONL 数据」以执行代码。
4. 编辑内置算子时，「更新库中此算子」会让这张库卡今后拖出新版，「另存为新算子」会增加一张卡。若要更新一张已有图，点画布上的节点，使用「编辑本节点代码」并保存流水线。已经启动的任务保留启动时的版本。

算子库卡片显示该算子的最近保存时间，画布节点的属性显示该节点最近一次随流水线保存改动的时间。流水线标题和目录显示最近一次正式保存的时间，按浏览器本地时间显示到秒。拖动节点位置并保存会更新流水线时间。算子的代码、名称、说明或参数发生改动并保存时会更新算子的时间。没有保存时间的旧数据会注明无记录。

内置提词和提示词改写使用 amax 本地的 Qwen3.8-27B-FP8。分割使用 GenCeption 14B，由 UMT5-XXL 编码目标短语。ABS 评分通过 API 调用 gpt-6.2-sol。视频输入、质量门控、结果输出和内置文本处理算子均显示「未调用模型」。自定义代码可在代码编辑器中填写运行时模型及接入方式，也可以随后编辑算子说明。

### 保存后的编排审查

编排页的「保存后自动审查」默认开启。点击流水线「保存」后会留出 3 秒，再检查这次保存的版本。等待中或审查中均可点「取消本次审查」。取消只影响这次检查，刚保存的版本仍然保留。关闭总开关会停止自动检查，浏览器会记住偏好，随时可点「审查已保存版本」手动检查。

审查会检查连线、分支、循环和执行模式的参数限制，也会在 amax 校验自定义 Python 的语法及入口。真正启动时仍会按执行方式检查当前图、输入材料和运行条件。审查本身不会启动分割或调用评分模型。

手部分割节点的编辑器会显示服务器源码的文件名和入口。Qwen、GenCeption、ABS、质量门控和提示词改写直接对应 DataFlow 算子类。视频输入对应清单导入函数，输出对应接收最终 JSONL 路径的工作台回调。编辑时保留入口名称、形参和进度装饰器。真实启动时，服务把本次版本和所需 Python 模块冻结到该任务的 `workbench/<任务标识>/source/`，执行这个副本。自定义视频代码以服务器任务账号运行，启动窗口会要求审阅。

## 让 DataFlow Agent 帮写代码

服务器集成了 DataFlow 仓库历史版本 `8f78a389` 的 Writer。编辑器把当前源码和设计需求交给配置的模型，Writer 返回候选 Python。可以先用一句包含输入、规则和输出的需求，例如「输入每条记录的 text，去掉首尾空白，转小写，写入 clean_text，并保留原字段」。在「Agent 设计」中生成草案，阅读后点「用草案替换编辑区」，再检查、试跑、保存。手部视频算子可以做接口检查，实际分割由你显式启动。编辑器中的 JSONL 样例只用于记录算子试跑。

工作台默认复用服务器上 ABS 的 OpenAI 兼容 Chat Completions 接口。地址、超时和密钥变量名来自 `~/scoring_scripts/abs/api_config.json`，模型来自 `extensions/qwen_gencep/pipeline.py` 的 `ABS_MODEL`，当前为 `gpt-6.2-sol`。Writer 发送算子代码和设计需求。ABS 的视频、掩码及评分记录留在原任务中。

如果你平时运行 ABS 的 **amax 终端**已导出 `MODEL_API_KEY`，在那个终端执行以下两行，把变量交给用户服务，再打开算子编辑器。

```sh
systemctl --user import-environment MODEL_API_KEY
systemctl --user restart flow-studio.service
```

要让工作台在重新登录或服务器重启后也能读取这个变量，可在 **amax** 上为服务配置个人环境文件。

```sh
mkdir -p ~/.config/flow-studio
touch ~/.config/flow-studio/agent.env
chmod 600 ~/.config/flow-studio/agent.env
nano ~/.config/flow-studio/agent.env
```

在编辑器里填入下面这一项，将占位内容换成你运行 ABS 用的密钥。

```ini
MODEL_API_KEY=你的ABS密钥
```

保存后运行 `systemctl --user restart flow-studio.service`，在浏览器中重新打开算子编辑器即可查看配置状态。若以后想为 Writer 单独指定服务，可在该文件显式配置 `FLOW_STUDIO_AGENT_BASE_URL`、`FLOW_STUDIO_AGENT_MODEL` 和服务所需的 `FLOW_STUDIO_AGENT_API_KEY`。编辑器的手写、检查和试跑可独立使用。

## 服务器运行

在编排页点「启动任务」会先打开方式选择窗口。视频图默认选中流程演练。选中「服务器视频分割」后，在「本次目标命令」输入「找手」或「找物」，也可以从命令建议中选择。内置「手部实例分割」的新启动和新预设默认找物。其他流水线沿用视频输入节点的目标设置。启动窗口的命令只用于本次任务，整份清单或队列使用同一个目标。

找手识别与物体交互的手，默认输出到 `/data/yanghonglei/DataFlow/dataflow_output/hands/`。找物识别被手操作的物体，默认输出到 `/data/yanghonglei/DataFlow/dataflow_output/objects/`。从工作台选择数据集后，新输出子目录会使用清单的序列名、序列文件夹名或视频文件名。遇到重跑或同名时追加数字后缀，例如 `subject1_k2_6-02`。提示词改写继续描述评分较低的同一目标。找物时 Qwen 还会保留物体类别和可靠外观，并可用有视觉依据的相对位置或接触关系补充描述。带有自定义服务器 Python 的图需要在启动窗口确认已审阅源码。

### 从服务器数据集选择序列

1. 在支持服务器视频分割的图上点「选择数据集」，或在「启动任务」里选择服务器执行。填好「本次目标命令」后再选序列。「数据目录」可选 `/data/yanghonglei/datasets` 或 `/data/xuzhefeng/video_object_phrases/datasets`。在共享目录里可按数据集筛选或搜索序列，再点序列检查。索引中的 RGB 镜像与原序列只列一次。添加素材后可以刷新列表。
2. 点一条序列，查看识别到的 RGB 视频、分辨率、原始帧率、帧数和时长。若发现多路原始视频，先选本次使用的视角。缺视频、视频无法读取或输入不满足要求时，检查结果会说明需要补充或调整的材料。原有手部分割图只需 RGB 视频，目标短语和掩码由流水线生成。
3. 原生入口每条视频要求 30 fps、1～81 帧，且宽高为正偶数。较长或帧率不同的序列可选「整条序列」或「选取片段」。整条按 30 fps 分段，每段最多 81 帧。含「全视频掩码融合」的编排中，相邻窗口共享 8 帧。片段从指定起始秒开始，在 30 fps 时间轴上最多取 81 帧。
4. 核对输入方案、片段数和输出位置。通过检查后点「确认启动」。工作台在服务器的私有工作目录准备本次 RGB 素材和 JSONL，其中每行的 `task` 按本次目标统一写作 `hands` 或 `objects`。材料变化会要求重新检查。本次目标、序列、范围和输出目录可在监控详情中查看。

「全视频掩码融合」在整条序列的片段完成后执行。序列输出目录中的 `whole_video_masks/track_*.npy` 每个文件对应一个视频级实例，形状为 `(帧数, 高, 宽)`。`tracks.json` 记录所用片段、轨迹、接缝和没有掩码的区间。展开「数据排队」中的序列可查看待复核的接缝。启用了质量门控的编排只融合通过的掩码。

共享包中的连续 RGB 视频按素材清单记录的原始帧率解释。若容器使用 1 fps 编号，页面会同时说明原始帧率和封装帧率。独立图片合集或缺少拍摄时序的稀疏帧也可以在列表中查看，预检会提示需要补充的原始连续 RGB 或时序资料。

### 按顺序处理多条序列

按住 Ctrl 点选多条序列，或用 Shift 连选，然后点「加入处理队列」。多选按整条视频检查。需要单独设置视角、截取范围或起点时，逐条配置并加入。同一个队列可以从两个数据目录添加，页面会列出无法加入的序列及原因。用「上移」「下移」「移除」确定顺序，核对条数和队列输出目录，点击「启动队列」。

amax 会保存每次提交的流水线版本，将单条任务、批次和手动输入清单统一排入服务器队列。服务器一次处理一条，当前任务结束后才开始下一条的准备工作。提交后进入「运行监控」，可查看排队、准备视频和算子进度。多条序列在批次目录下按序列名输出。关闭网页或 SSH 转发后服务器会继续工作。某条失败或中断时，同一批次的余下条目暂停，其他批次可继续。

服务器数据集启动窗口和「使用预设任务」均显示「执行顺序」。一条序列拆为多段时，首段先走完提词、分割和已启用的评分等步骤，其余片段按算子分批推进。运行事件中的「首段」和「其余片段」对应这两个阶段。启用全视频掩码融合的序列，在所有片段完成后执行一次融合。

在「编排设计」「运行监控」旁打开「数据排队」，可查看服务器上的执行中序列和全局待处理顺序。拖动待处理序列，或用上移、下移调整，支持跨批次。准备视频和已开始运行的序列锁定。

展开序列的片段清单，可以按 30 fps 输入时间轴查看从 0 开始的帧范围，以及该片段当前的算子、完成状态和反馈轮次。每条数据集任务只有一段时直接执行。存在多段时，先完成首段，余下片段再按算子分阶段处理。内置提词共用一个 Qwen 实例，GenCeption 分别在编码、推理和解码阶段复用模型，每轮提示词改写只为待改写的片段启动一个 Qwen 实例。不同数据集序列仍按服务器队列依次运行。旧任务的片段状态来自当时已记录的进度。

点击页面顶部「预设任务」，填写任务名、选择找手或找物，再选择序列和处理范围。当前编排包含 ABS 或质量门控时，可以为此预设调整采样间隔或通过阈值。真正要运行时，从「启动任务」选择「使用预设任务」，核对设置并点「加入队列」。启动时会重新检查素材，并用最新的已保存编排和算子代码运行。预设的目标、序列和适用于当前编排的评分参数会随任务一起提交。

### 流水线说明与 GPU 监控

编排设计或运行监控旁边的「说明文档」属于当前流水线。在文档中编辑正文、插入本机图片并保存。图片和正文位于工作台的 `.local/pipeline-docs/`。保存文档使用独立修订号，多窗口编辑冲突时可核对文本再合并。文档及插图不作为算子输入。

在左侧「GPU 占用」中查看 amax 的每卡利用率、已用及总显存、温度和可见的计算进程。面板打开时定期刷新，也可以手动刷新。

### 手动使用已有输入清单

在运行对话框中选服务器执行，填入已有 JSONL 清单。清单每行的 `task` 都必须与本次选定的目标一致，即 `"task":"hands"` 或 `"task":"objects"`。工作台预填对应的新输出子目录，也可以填写账号家目录内尚未存在的其他路径。清单格式示例见[工作台使用指南](../WORKBENCH.md#4-提交任务和查看结果)。

桥接支持当前服务器已有的三种执行方式。每条图从输入节点开始，依次提词和分割，再直接输出，或追加 ABS 后输出，或追加 ABS 和完整的质量反馈。采样间隔和质量阈值会传递给原 CLI。Qwen 固定每秒 5 帧，每个实例的最大重试次数固定为 2。服务器新任务使用原 CLI 的 GPU、模型及本地编码器默认配置。其他算子和分支可在演练模式检查流程。

完成真实启动后，原 CLI 在 `--out` 路径写入原有产物。桥接为这次请求在服务器 `~/.local/state/dataflow-qwen-gencep/workbench/` 记录输出路径、版本图、进程标识与启动日志。同一份请求重复提交时返回原受理结果。启动后刷新即可查看进度；第一次算子进度写入前可能短暂处于等待状态。

## 进度依据

初轮 ABS 因模型 API 连接超时、限流或服务暂时不可用而失败时，可在「运行监控」选中失败的服务器任务，再点「继续执行」。续跑复用已完成的提词和分割，按原评分程序验证输入快照及首答，只补尚未收到响应的请求。完成后继续原有质量反馈和未运行片段。此入口适用于带完整初轮 ABS 检查点的内置算子流程。续跑仍进入全局服务器队列。

工作台复用原监控器的状态记录和进程存活校验，展示找手和找物的运行。新一轮分割记录和每轮 `feedback_step1.jsonl` / `feedback_step2.jsonl` 中出现的实例决定提供支路证据。多个实例可以分别进入不同支路，图中可同时保留多条已观察到的路径。已有状态记录只保存每个算子的起止时刻和最近一次活动，时间线按这些事件展示。运行完成表示流水线执行结束，实例也可能进入待复核。
